# generate

Writes a policy repo's enforcement from its policy files, so nobody edits CODEOWNERS, branch protection, role
workflows or schedules by hand. CI runs it in **check** mode and fails on any drift; a person runs it in **write**
mode after changing `config.yaml`, `repos/` or `roles/`, and commits what it writes.

| File | From | What it is |
| --- | --- | --- |
| `.github/workflows/role-<role>.yml` | each agent role with a `run` | The role's triggers (`workflow_dispatch` with `signal` and `clock`) and a call to this repository's `.github/workflows/role.yml`, pinned to `airlock_actions.ref`. No `schedule:` trigger: the clock is the only timer. |
| `generated/codeowners/<repo>.CODEOWNERS` | `repos/<repo>.yaml` | Commit as that repository's `.github/CODEOWNERS`. An L1/L2 default owns everything; an L1/L2 path stricter than the default gets its own line; `/AUTONOMY.yaml` is always owned. |
| `generated/branch-protection/<repo>.json` | `repos/<repo>.yaml`, `config.yaml` | The body for `PUT /repos/<org>/<repo>/branches/main/protection`. |
| `generated/roles/<role>/github-app.json` | `roles/<role>/role.yaml` | The permissions of a role's own GitHub App, from its `writes`; only for a role not on Airlock (`identity.key_store` other than `airlock`). Roles sharing a `github_login` share one App. |
| `generated/schedules.json` | every agent role's `run.schedule`, and `config.yaml` `clock` | What a clock dispatches, and when (UTC cron), each with `clock: "true"`. |

A generated file nothing produces any more (a removed repository or role, a role that moved onto Airlock) is drift
too: check fails on it, write deletes it. A role workflow without the `# GENERATED by <policy repo>` first line is
hand-written and never touched.

## In CI

```yaml
# .github/workflows/validate.yml, in the policy repo
jobs:
  validate:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@<sha>
      - name: generated enforcement matches policy
        uses: lunareng/airlock-actions/generate@<sha>   # mode: check is the default
```

Inputs: `mode` (`check` or `write`, default `check`), `policy` (the checkout's path in the workspace, default `.`),
`repo` (the policy repo's full name, default `github.repository`). Output: `stale`, how many files are stale. Each
stale file is an error annotation on its path.

## Writing

From a checkout of this repository at the commit your policy pins:

```bash
python3 path/to/airlock-actions/generate/generate.py --policy path/to/policy --write    # needs pyyaml
```

`--repo owner/name` names the policy repo; without it the generator uses `GITHUB_REPOSITORY`, then the checkout's
`origin` remote. A missing or malformed setting is an error, and nothing is written.

## Settings, in the policy repo's `config.yaml`

| Key | Required | Default | What |
| --- | --- | --- | --- |
| `human_owner` | yes | | The CODEOWNERS owner of every L1/L2 path, e.g. `"@acme/owners"`. |
| `required_checks.default`, `required_checks.<repo>` | yes | | Each repository's required status checks. |
| `strict` | no | `[]` | Repositories whose checks must pass on the current base before merge. |
| `owner_review` | no | `false` (`true` or `false`, unquoted) | Require the code owner's review on L1/L2 paths. Turn it on once every agent commits under its own login. |
| `clock` | no | `[]` | Timed workflows that aren't agent roles: `{workflow, cron, inputs}`. |
| `airlock_actions.ref` | yes | | The commit SHA (40 hex) or `vX.Y.Z` release of lunareng/airlock-actions every generated caller pins. |
| `airlock_actions.note` | no | | A one-line comment after the pin, e.g. what the commit is. |
| `role_runs.runner` | no | role.yml's (`ubuntu-latest`) | The runner label role runs use. |
| `role_runs.git_email_domain` | no | role.yml's (`users.noreply.github.com`) | Role commits are `<role>@<domain>`. |
| `generated.codeowners` | no | `generated/codeowners` | Where the CODEOWNERS files go. |
| `generated.branch_protection` | no | `generated/branch-protection` | Where the protection bodies go. |
| `generated.apps` | no | `generated/roles` | Where the GitHub App permission files go. |
| `generated.schedules` | no | `generated/schedules.json` | Where the schedules go. Keep it where your clock reads it. |
| `generated.schedules_reader` | no | `the clock` | Who reads the schedules, named in the role workflows' and schedules' comments. |

Every generated path must be inside the policy repo and outside `.github/`. Every cron is five UTC fields of digits, `*`, `/`, `,` and `-`; a clock entry can't set the `clock` input, which is what holds a timed run to `AGENTS_ENABLED`; a hand-written `role-<role>.yml` for an agent role is an error, never overwritten.

```yaml
# acme's config.yaml
human_owner: "@acme/owners"
required_checks:
  default: ["autonomy-gate", "claude-review"]
  policy: ["validate"]
airlock_actions:
  ref: 0123456789abcdef0123456789abcdef01234567
role_runs:
  runner: acme-agents
  git_email_domain: acme.example
```

## Tests

`python3 test/generate/test_generate.py` runs it on an invented acme policy repo, `test/generate/fixtures/policy`,
which carries the generated files committed as a tenant would. With `REPRODUCE=<policy checkout>` and
`REPRODUCE_REPO=<owner/name>` it also checks that checkout's committed files byte for byte.
